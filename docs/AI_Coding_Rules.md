# AI Coding Rules

- 不允许随意更换技术栈。前端固定 React、TypeScript、Vite、Ant Design；后端固定 FastAPI、SQLAlchemy、SQLGlot；数据库固定 PostgreSQL。
- 不允许删除已有功能。重构前必须确认功能等价，并保留 SQL 解释、风险检查、历史记录和 Dashboard。
- 不允许引入未确认的新依赖。新增依赖必须说明用途、替代方案和影响范围。
- 修改代码前先说明影响范围，尤其是数据库 schema、接口返回格式和前端路由。
- 新增功能必须同步更新 README 和 docs。
- 后端接口返回格式必须统一为 `{ "code": 0, "message": "success", "data": {} }`。
- 前端页面风格必须统一为简洁、专业的企业后台风格。
- 不把 API KEY、数据库密码或公司内部连接信息写死在代码里。
- 不连接真实公司生产数据库，不执行用户输入 SQL。
- V1 不实现登录、Text-to-SQL、复杂 Agent、多租户和复杂权限。
- 公司数据库接入默认只允许只读采集元数据，不读取真实业务明细数据。
- 好股库表结构和指标口径应优先从 `ai_platform` 元数据表同步，不应从本地 SQL 文件或文档中猜测生成。
- 不允许把真实公司数据库账号、密码、内网地址写入项目文档、代码或 seed 数据。
- 不允许向 `database/seed.sql` 写入虚拟业务表、虚拟字段或虚拟指标口径；本地元数据应来自只读同步或明确标注的测试数据导入。
- 早期本地 SQL/Markdown 推断导入脚本不得写入公司元数据；如需补充元数据，优先修正 `ai_platform` 源端或新增受控只读同步逻辑。
- 元数据可视化、搜索和详情页面默认只能读取本项目 PostgreSQL 中已同步的元数据，不得直接读取公司业务明细表。
- 敏感字段识别默认只能使用源端元数据标签或明确提供的规则，不得通过扫描真实业务明细数据来推断敏感性。
- 存储过程血缘只能读取系统目录和过程定义元数据，不得执行存储过程，不得执行高风险 SQL，不得读取真实业务明细数据。
- 存储过程全量同步必须分批读取元数据，避免对链接服务器发起长时间大查询；动态 SQL 解析结果必须标记为需复核。
- 数据字典网页同步只能使用临时浏览器会话 Cookie，不允许把 Cookie、账号、密码或内部会话信息写入代码、文档或日志。
