# PRD

## 项目背景

金融数据开发工作中，SQL 分析、字段口径确认、指标解释和数据风险识别高度依赖经验。Finance Data Copilot 希望把这些高频工作沉淀为一个可演示、可扩展的 AI 数据开发助手。

## 目标用户

- 金融数据开发工程师
- 数据分析师
- 指标管理和数据治理人员
- 希望展示 AI + 数据工程能力的个人开发者

## V1 核心需求

- SQL 解释：快速理解 SQL 类型、涉及表、字段、JOIN 和过滤条件。
- SQL 风险检查：识别常见危险 SQL 和低效 SQL 模式。
- 历史记录：保留每次 SQL 分析结果，便于回溯和展示。
- Dashboard：查看分析总量、风险分布和近期趋势。
- 元数据全景：基于已同步的好股库元数据，展示表、中文名称、字段、业务域、下线状态、敏感字段和大尺寸业务域资产矩阵，表资产列表排序必须在后端全量排序后再分页。敏感字段当前只依据源端 `pii_level` 元数据映射，不扫描真实业务明细数据。
- 存储过程血缘：基于好股库链接服务器的系统目录，只读获取存储过程定义并解析过程到表的读取、写入、临时表和表间链路关系，不执行存储过程。动态 SQL 标记为需复核，并在页面中提供解析状态筛选、复核原因、语句片段和表影响分析。
- 血缘复核工作台：集中展示需人工判断的动态 SQL 过程和低置信度读写边，支持确认、标记需修正、忽略和备注，为后续提高血缘解析准确率沉淀人工反馈。
- 数据库初始化：沉淀后续数据字典、字段元数据和指标口径管理表。
- 好股库元数据同步：从公司 SQL Server 测试库中的 `ai_platform` 元数据表只读同步好股库表、字段和指标口径。

## V1 功能边界

V1 不实现登录系统、复杂权限、多租户、真实数据库执行 SQL、Text-to-SQL、SQL Agent 和复杂 RAG。公司数据库接入仅限只读采集元数据和存储过程定义，不读取真实业务明细数据，不执行用户输入 SQL，也不执行存储过程。元数据全景和存储过程血缘只展示本项目 PostgreSQL 中已同步和解析后的结果。

## 当前开发主线

当前阶段优先从元数据开始拆解处理，先明确好股库中哪些表可用、哪些字段可信、字段中文名和备注是否完整、主键和是否为空信息是否可靠。元数据质量稳定后，再继续完善存储过程血缘复核、表影响分析和 AI 问答能力。

短期优先级：

1. 元数据质量收敛：可用表、可用字段、主键、字段中文名、字段备注、字段类型和敏感字段口径。
2. 血缘分析闭环：存储过程血缘、低置信度边、动态 SQL 和人工复核。
3. AI 能力接入：基于可信元数据和血缘上下文做 RAG、指标问答和受控 Text-to-SQL。

## 后续版本规划

- V1.1：完善元数据全景、补充表字段搜索体验、完善存储过程血缘解析、增加过程影响范围搜索和表间链路复核能力、完善 SQL 解析细节、补充单元测试、增加导出能力。
- V2：接入真实大模型，支持更自然的 SQL 解释。
- V3：基于 metadata_table、metadata_column 和 metric_definition 实现 RAG 问答。
- V4：实现受控 Text-to-SQL。
- V5：探索 SQL Agent，但必须加入权限、审计和执行隔离。
